# 通用歌单与歌词操作

本文记录本轮完成的两组功能：**保留 HanMusic JSON 歌单交换，增加本地 M3U/M3U8 兼容；为本地同步歌词增加点击定位和同步偏移。** 代码在开发分支交付，尚未发布新的正式版本。

本轮开始前的代码基线 `0a14586` 已推送，识曲后台的 Linux / Windows CI 已通过。首次 Windows CI 的 688 项测试通过，但新版 MSVC 构建 WinRT 时报 STL1011；`8cb4238` 将应用目标切换到标准 C++20，随后[Windows CI](https://github.com/LiMuxing666/HanMusic/actions/runs/41031550513)全部通过。插件仍使用各自原有编译设置。微软官方的[协程编译选项说明](https://learn.microsoft.com/en-us/cpp/build/reference/await-enable-coroutine-support?view=msvc-170)解释了旧实验接口的弃用。上述结果属于基线及构建修复，新增功能验证单独记录如下。

## 2. 导入通用歌单

在“歌单”页面点击“导入歌单”，选择 `.json`、`.m3u` 或 `.m3u8` 文件。原 HanMusic JSON 格式继续兼容，并保留在线歌曲的稳定源标识及歌曲身份。

所有格式先显示导入预览：新歌单名称、格式与编码、歌曲总数、在线与缺失数量，以及适用的重复合并和跳过数量，并列出前五首歌曲。确认后仅创建新歌单，不导入曲库、不改变播放队列、不自动播放；取消预览不创建歌单。缺失项会保留，供以后恢复文件后使用。

### 编码与路径规则

- `.m3u8` 必须为 UTF-8，可带 UTF-8 BOM。`.m3u` 先按 UTF-8 读取，失败时兼容严格 GBK；GBK 仅用于 M3U 导入，没有 GBK 导出。UTF-16 文件会被拒绝，并提示另存为 UTF-8 M3U8。
- 接收带盘符的 Windows 本地绝对路径，例如 `D:\Music\夜航.flac`。普通相对路径以歌单文件所在目录为基准，允许 `..`，例如 `..\Music\夜航.flac`。
- 可接收本地 `file:` URI，但不能包含主机名、查询参数或片段。路径必须指向曲库支持的音频类型。
- 网络 URL、UNC 网络共享路径、设备路径、NTFS 附加数据流、`C:歌曲.mp3` 一类盘符相对路径，以及 `\Music\歌曲.mp3` 一类根相对路径不受支持。嵌套歌单、非音频和其他不支持的路径会计入跳过数量。
- 遇到 `#EXT-X-` HLS 指令时拒绝整个清单，并提示选择本地音频歌单；本轮不将 HLS 清单作为普通歌单展开。

`#EXTINF` 仅用于读取下一条歌曲路径的显示名称和有效的非负时长；未知或异常时长按未知处理，不推断歌手、专辑或音频标签。处理下一条路径后即清除该信息，包括该路径被跳过的情况。其他普通注释和空行不作为歌曲导入。

重复歌曲按现有歌曲 ID 合并，保留首次出现的顺序。每个文件最多 **4 MiB**，最多读取 **5000 条歌曲路径**；跳过项和重复项同样计入路径上限。此外，文本最多 20000 行、单行最多 4096 个字符。超限或编码损坏时拒绝导入，不创建部分歌单。

导入仍会检查本地文件是否存在；不可访问、缺失或检查超时的项标记为缺失。歌单文件只记录路径，跨机器使用时仍需要目标机器上的路径有效，不会复制音频或自动寻找搬迁后的文件。

## 3. 导出 JSON 或 M3U8

“导出 JSON”继续用于保留完整的 HanMusic 歌单信息，包括在线歌曲的稳定身份。“导出 M3U8”生成 UTF-8 扩展歌单，包含 `#EXTM3U`、`#EXTINF` 和 Windows 本地音频的绝对路径，供其他播放器读取。

M3U8 只导出受支持的本地音频路径，缺失的本地路径也会保留。歌单中含在线歌曲或不支持的路径时，先显示将导出及跳过的数量，由用户确认后继续；没有任何可导出的本地歌曲时提示改用 JSON，不生成空歌单。

两种导出均选择目标文件夹；同名文件自动添加编号，保留已有文件。导出不复制音频、封面或 LRC，不写入在线临时播放地址，也不改变当前播放状态。

## 4. 歌词点击定位与同步偏移

在“正在播放”页面打开同目录同名的本地 `.lrc` 歌词。带有效时间戳的歌词行可点击定位至对应播放时间：正在播放时继续播放，暂停时保持暂停。没有时间戳的纯文本歌词不提供定位；没有可用歌曲、正在加载、时长未知或退出处理中时不执行定位。

歌词同步提供“提前”“延后”和“重置”操作，每次调整 **0.5 秒**，范围为 **提前 30 秒至延后 30 秒**。界面显示当前调整量；到达边界后不能继续沿同一方向调整。调整只改变歌词时间对应关系，不单独改变音频进度。

例如某行解析后的时间为 `00:20`，设置“歌词延后 1.0 秒”后，该行在音频 `00:21` 附近显示；点击该行也定位到 `00:21`。显示与点击使用同一偏移，最终定位限制在 `0` 到歌曲总时长之间。LRC 自带的 `[offset]` 已在解析时处理，用户调整在该结果上叠加，不重复解析文件偏移。

调整量按歌曲记录在**本次运行的内存中，最多保留最近调整的 128 首歌曲**。切换页面、切到其他歌曲再切回仍保留；超过容量时淘汰最早保留的调整，重置会移除该歌曲的调整记录。退出并重新启动应用后恢复为零。它不写入应用状态、音频或 LRC 文件。

点击歌词行仍通过现有播放服务的 seek 操作，并保留当前选曲代次检查，避免旧歌词操作影响新歌曲。播放历史的“真实累计 10 秒”规则继续适用，跳转跨过的时间不能当作已播放时间。

## 5. 数据兼容与范围

本轮不增加持久化字段，应用状态保持 **schema 5**，HanMusic JSON 交换文件保持其独立格式版本。已有曲库、队列、歌单、历史、主题和设置的迁移及未来版本只读保护继续沿用。

M3U8 不能完整表达 HanMusic 在线源身份；需要完整备份或转移包含在线歌曲的歌单时使用 JSON。歌词仍采用已有本地旁置文件读取方式，本轮不增加在线歌词服务、内嵌歌词编辑或文件写回。
