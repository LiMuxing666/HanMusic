# Windows M5 高速滚动视口覆盖复核

日期：2026-10-02。产品仍为 `0.1.0-dev.16+16`，本轮只修改独立 Profile 性能探针，没有修改正常播放器页面或重新打开发预览包。

## 为什么补充此指标

既有探针让 10,000 条合成曲库在 10 秒内走完整个列表，并按实际经过时间在每个 Ticker 用 `jumpTo` 更新位置。帧数变少时，单次跳跃变大；即使测量时间和累计滚动距离接近，进入视口的行数也可能不同。上一轮独立行生命周期诊断在约三次单程扫过中记录 10,007 次宽行挂载，只能说明实际创建频繁，不能把未请求的曲目当成已渲染。

新探针在测量期每个 tick 仅保存目标 offset 和当时的实际 viewportDimension，在收尾阶段计算相邻两个**请求视口** `[offset, offset + viewportDimension)` 是否相交，以及两者之间的正空档、绝对位移。记录数必须等于滚动 tick 数，否则采集判为未完成。空档总量按相邻对相加，往返时可能重复计算同一范围；该指标不是已绘制行数、独立曲目数或系统滚轮输入。

## 决定与剩余工作

**单看 UI p95 不能证明候选减轻了相同的行工作量。** 本轮每对相邻请求视口都有空档；对于未来 A/B，须固定同一探针、窗口、构建模式和 10,000 条数据，同时检查帧数、滚动 tick、正空档比例与总量、目标位移和 UI/raster p95。差异明显时，应先解释覆盖差异，再判断代码收益。请求视口仍不等于真正绘制的行；需要时可另做有界诊断，但不得把带行包装的帧率与正常页面比较。

本次 13.953 ms 是一次有效的合成压力采集，不能覆盖跨轮波动、真实文件/封面、物理音频、原生窗口、系统 DPI 和干净机器等 M5 验收。没有运行全量自动测试、正常 Release 构建或重新打包。只对改动探针做定向静态/格式检查，并运行上述一次 Profile 采集。M5 仍在进行中。
