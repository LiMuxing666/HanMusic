# HanMusic 技术架构要求

> 版本：v0.8　　日期：2026-09-30
> 状态：Windows M1–M4 核心已实现；M5 性能与开发预览验收进行中，原生系统 UI、真实休眠和公开发行条件仍待完成
> 关联文档：[02-需求文档](./02-需求文档.md)、[03-功能说明文档](./03-功能说明文档.md)

---

## 1. 总体原则

1. **MVVM 分层**：View 负责展示与绑定，ViewModel（GetXController）编排交互，播放、导入和持久化业务收敛在 Repository/Service。禁止在 Widget 中写业务逻辑。
2. **依赖极简**：能不用第三方包就不用；引入前需评估维护活跃度与全平台支持度。用成熟轮子，不重复造轮子。
3. **面向抽象编程**：播放器、数据源、持久化均以接口/服务抽象暴露（如 `PlayerService`），底层实现可替换（本地文件 / 网络流 / 不同平台实现）。
4. **一次编写，多端运行**：所有业务代码平台无关；平台差异通过适配层（Adapter/条件导入）隔离，不允许在业务代码中散布 `Platform.isXxx` 分支。
5. **可测试**：ViewModel 与 Repository 依赖注入，可被 Mock，核心逻辑可脱离 UI 做单元测试。

| 网络图片缓存 | cached_network_image | 在线封面列表出现加载卡顿时 |

> 依赖准入规则：新增任何依赖需在本文档"选型表"中补充条目并说明理由；同类能力的包只允许存在一个。

Windows 初始化调用 `JustAudioMediaKit.ensureInitialized(windows: true, linux: false)`，再创建播放器。实际原生音频由 libmpv 提供；Release 必须包含 `libmpv-2.dll`、`media_kit_libs_windows_audio_plugin.dll` 及 Flutter 运行文件。当前 native 包固定使用 2023-09-24 的 libmpv 构建；M5 已核对二进制来源与许可，但完整对应源码/静态依赖材料尚未闭合，详见 [Windows 依赖与分发检查](./11-Windows依赖与分发检查.md)。包装插件许可不能替代原生库许可，本轮没有升级依赖。

`JustAudioBackend` 针对桥接库错误事件不会结束加载 Future 的行为，将加载结果与错误流并行等待，并设置 15 秒超时；失败时停止并释放原生实例以支持重新导入。`PlayerService` 使用加载序号和播放意图序号，避免迟到的加载结果覆盖错误或定时暂停。UI 只依赖 Controller/Service，不直接访问播放器库。

M2 验证结果与限制见 [Windows M2 验证记录](./07-Windows-M2验证记录.md)。自动测试、原生诊断入口与 Flutter 渲染预览分别记录，不将其合并为系统文件对话框或窗口操作已经验收。

## 3. MVVM + GetX 分层架构

```
┌─────────────────────────────────────────────┐
│  View（Widget）                              │
│  页面/组件，Obx/GetBuilder 绑定状态，零业务逻辑 │
└──────────────▲──────────────────────────────┘
               │ 响应式状态 (.obs / Rx) + 用户事件回调
┌──────────────┴──────────────────────────────┐
│  ViewModel（GetXController）                 │
│  页面状态、交互逻辑、调用 Repository/Service   │
└──────────────▲──────────────────────────────┘
               │ 接口依赖（构造注入 / Get.find）
┌──────────────┴──────────────────────────────┐
│  Service / Repository（业务与数据访问层）      │
│  PlayerService / TimerService / ...          │
│  LocalMusicRepo / OnlineMusicRepo / ...      │
└──────────────▲──────────────────────────────┘
               │ 数据源
┌──────────────┴──────────────────────────────┐
│  DataSource：文件系统 / AppStateStore / HTTP API │
│  （just_audio 等第三方只出现在本层）           │
└─────────────────────────────────────────────┘
```

分层规则：

- **View → ViewModel**：单向调用与监听，View 可读取不可变 Model 展示信息，不直接调用 Repository 或音频 SDK。
- **ViewModel**：一个页面对应一个 Controller；跨页面共享的状态放全局 Service，Controller 只做转发。
- **Service**：全局单例（`Get.put` 永久注册），如播放器服务、定时服务、设置服务；与页面生命周期解耦。
- **Repository**：按数据来源划分（本地/网络），对上提供纯 Dart 接口，ViewModel 不感知实现。
- **第三方 SDK 隔离**：`just_audio`、`file_picker`、`audio_metadata_reader`、`http` 只允许出现在 data/service 层，便于日后替换实现。

### 3.1 目录结构约定

```

├── main.dart                 # 入口：初始化服务、注册路由、运行 App
├── app/
│   ├── core/                 # 通用基础层（与业务无关）
│   │   ├── constants/        #   常量（路由名、存储 key、默认配置）
│   │   ├── theme/            #   主题（亮/暗、通用样式）
│   │   ├── utils/            #   工具（时间格式化、文件大小等）
│   │   ├── extensions/       #   Dart 扩展
│   │   └── exceptions/       #   统一异常定义
│   ├── data/                 # 数据层

│   ├── modules/              # 页面模块（一个模块 = 一个 MVVM 单元）
```

模块内固定三件套：`view.dart`（页面）、`controller.dart`（ViewModel）、`bindings.dart`（依赖注入绑定）。

上图包含后续规划目录。实际将曲库、正在播放和队列三个视图放在 `modules/player`，通过 `library_widgets.dart` 组织桌面组件；已实现 `LibraryService`、`PlayerService`、`TimerService`、`AppPersistenceService` 和本地仓库。M4 已增加 `modules/online`、`OnlineMusicService` 与网络仓库；上图的 `online_source_service.dart` 是早期命名约定。独立歌单、歌词等后续模块不以目录约定视作已实现能力。

### 3.2 GetX 使用规约

- 路由：统一走命名路由（`Get.toNamed(Routes.PLAYER)`），路由名集中定义在 `app_routes.dart`。
- 注入：页面级依赖用 `Bindings`；全局服务在 `main.dart` 启动时 `Get.put(..., permanent: true)`。
- 状态：需要 UI 响应的状态用 `.obs` + `Obx`；纯逻辑内部状态用普通变量，避免过度响应式。
- Controller 生命周期：`onInit` 中做初始化/订阅，`onClose` 中释放订阅与资源；禁止在 Controller 中持有 BuildContext。
- 通信：跨模块通知优先用 Service 的 Rx 状态，其次 `Get.find` 调用方法；避免滥用事件总线。

## 4. 关键技术方案（已实现部分与后续设计）

### 4.1 播放器

- M2 的 `PlayerService` 通过 `AudioBackend` 使用音频实现，对外暴露当前歌曲、播放/加载状态、位置、时长、队列和模式等 Rx 状态。
- 队列支持指定曲目起播、增删、重排、上一首/下一首和四种模式。顺序模式自然播放到末尾停止；单曲循环作用于自然结束，手动切歌仍切换曲目。缺失或损坏文件按跳过设置处理，并限制失败遍历，避免无限循环。
- 重启恢复队列、当前曲目、进度、模式、音量和自动跳过设置，保持暂停就绪态；首次点击播放才加载音源并恢复进度，不在启动时自动播放。
- M2 曲库使用本地文件 URI。网络源和临时 HTTP 播放地址在 M4 接入，复用同一播放服务。
- 移动端设计由 `just_audio_background` / `audio_session` 处理后台和中断。Windows 当前仅在应用进程内播放；SMTC、全局媒体键与托盘均未实现。

### 4.2 本地音乐库

- M2 通过 `LibraryPicker` / `LocalLibraryPicker` 选择多文件或目录，目录包含子文件夹；导入只入库，点击曲库歌曲后才按当前搜索结果建立队列播放。取消选择不改变已有状态。
- `LocalLibraryRepository` 规范化本地路径，`Song.id` 对 Windows 文件 URI 按大小写不敏感规则去重；移除索引和队列条目不删除源音频。启动及手动检查更新缺失标记。
- 每次导入复用一个后台 isolate 读取元数据，单文件读取/工作进程初始化设超时，取消时终止工作进程；已成功导入的条目保留。标题、歌手、专辑文本截断到 512 字符，解析失败或超时以文件名及默认封面降级，不保证每种编码都有完整标签。
- 封面优先选前封面，仅允许 PNG/JPEG、最多 4 MiB、宽高各不超过 4096 像素；按内容摘要缓存到应用数据目录的 `artwork`。不支持、超限、损坏或缓存失败时使用默认图形，不修改源文件。
- 曲库使用 `ListView.builder`，队列使用 `ReorderableListView.builder`；底部播放条固定，标题/歌手/专辑搜索与缺失灰显已落地。M5 按文字比例设置固定行高，并约束曲库行预取/保活开销。万文件扫描与实际页面 Profile 是两组独立证据，详见 [M5 阶段验证记录](./13-Windows-M5阶段验证记录.md)；高速跳转负载下 UI p95 从 41.127 降至 22.414 ms，仍未达到 16.7 ms 目标。

### 4.2.1 状态存储与恢复

Windows 入口在读取 store 前取得 `DataDirectoryLock`，按规范化目录串行化同一目录的多个进程；锁句柄保留至进程终止，避免超时写盘与新实例竞争。`AppShutdownCoordinator` 分离可取消的保存阶段与有界清理阶段：`flush()` 返回结果，失败须由用户选择返回或放弃；取消保持服务可用，确认后停止监听但不重复保存。宿主在等待期间阻止页面编辑，正常关闭仍走 Flutter 的 `didRequestAppExit`，不另写 Win32 关闭拦截。实现与验证范围见 [M5 数据保护与退出记录](./14-Windows-M5数据保护与退出验证.md)。

- `AppSnapshot` schema 2 保存曲库、混合队列、当前歌曲 ID、进度、播放模式、音量和自动跳过设置；读取并迁移 schema 1。在线项只允许出现在队列，保存稳定逻辑身份，不保存临时 HTTP 地址。睡眠定时不进入快照。
- `AppPersistenceService` 合并频繁变更并周期保存播放进度；关闭时等待保存。`AppStateStore.save()` 返回可等待的 Future，文件实现串行写入临时文件、保留上一份有效备份再替换主文件，避免把内存更新误当作落盘完成。
- 主文件损坏时尝试有效备份；遇到不支持的新 schema，或主文件与备份均不可用时，保留原文件并进入只读保护，提示本次更改不会保存。数据目录不可访问同样报错，不静默覆盖原数据。
- 数据目录优先使用绝对路径环境变量 `HANMUSIC_DATA_DIR`，否则由 `path_provider` 获取系统应用支持目录。本机配置为 `D:\dev\data\HanMusic`，不是程序硬编码的发布路径。M2 不持久化 API Key，后续敏感信息仍需安全存储。

### 4.3 网络音乐源

- `OnlineSourceConfig` schema 1 定义匿名 GET JSON、同源端点、查询参数、点分字段映射、分页与总超时。配置、响应及复现服务见 [网络源协议](./09-Windows网络源协议.md)，不硬编码第三方音乐 API。
- `OnlineMusicRepository` 负责 HTTP、受限响应读取、字段解析和安全错误；`OnlineMusicService` 管理 500ms 搜索防抖、请求取消/序号、分页、测试与源修订。旧搜索和旧配置解析不能覆盖新状态，API 本身不自动重试。
- `FileOnlineSourceStore` 在 `online` 子目录串行保存配置、有效备份与选择状态；测试成功并等待落盘后才发布内存变更。损坏或不支持的新 schema 采用只读保护。
- `Song.online` 使用源 ID + 歌曲 ID 构造稳定 `hanmusic://track/...` 身份，复用同一队列与 `PlayerService`。每次原生加载前经注入的 resolver 取 HTTP(S) 地址；首次原生加载失败重新解析并加载一次，解析错误不重试，自动跳过仍有界。
- 解析和重试均复查歌曲世代与 M3 播放意图，到期期间迟到返回不能自动起播。启动不解析、不播放，用户首次播放才取新地址。
- 网络错误不含请求地址和响应体。`JustAudioBackend` 通过专用 Zone 过滤桥接 MPV 的直接控制台输出，保留错误流供恢复处理；暂不支持认证配置或远程封面。

### 4.4 定时（睡眠定时器）

- `TimerService` 管理互斥的关闭、倒计时、按曲结束三种状态，不负责队列操作。`SleepTimerCoordinator` 实现 `PlaybackGuard`，把定时策略连接到 `PlayerService` 的完成、错误、自动切歌和实际起播边界，同步撤销过期播放意图，再异步暂停原生音频。
- 支持 15/30/60/90 分钟、自定义 1–1440 分钟、显示、取消、更换及顺延 10 分钟。顺延基于原截止时间；已过期任务不能被顺延复活。世代序号使旧回调不能暂停新的定时会话。
- 按曲结束绑定当前歌曲；暂停、继续和 seek 保留绑定，手动切换到其他歌曲或删除当前项会取消。目标歌曲完成或出错时消费任务并阻止自动推进，单曲循环也停止；正常完成后保持曲终位置，避免后端迟到的零位置覆盖。
- 使用绝对截止时间，周期检查、窗口恢复和 Windows `WM_POWERBROADCAST` 恢复事件均复查到期状态。原生 runner 经 `hanmusic/power` 通道转发恢复通知，Dart 适配器只检查截止时间；不阻止系统休眠、不申请唤醒、不自动恢复播放。
- 退出时注销通道、移除协调守卫并关闭定时服务；定时状态不进入持久化快照。实现与验收边界见 [M3 验证记录](./08-Windows-M3验证记录.md)，模拟墙钟和恢复消息不等于真实休眠验收。
- 定时到期使用 `pauseForSleepTimer()` 等待后端暂停结果；处理中显示正在暂停，确认成功后显示已停止，失败时明确告知。普通暂停继续使用安全错误提示。

### 4.5 AI 服务接入（歌词场景）

- 三家供应商（阶跃星辰 StepFun、智谱 AI、DeepSeek）均兼容 OpenAI Chat Completions 协议：**一个统一 REST 客户端**，供应商差异仅体现为内置预设（Base URL + 模型清单），不写三套对接代码。
- 用户配置 = 选择供应商 + 输入 API Key + 选择模型（预设下拉 + 允许自定义）；能力本期仅"歌词获取"，`AiService` 接口预留扩展位。
- 请求约束：非流式、超时 30s、保守采样参数；提示词约束模型只输出歌词本体（优先 LRC 带时间戳格式），不做解释性输出。
- 歌词链路（`lyrics_service`）：以（曲名 + 歌手）规范化为缓存键 → 本地命中直接展示，未命中才发起 AI 请求 → LRC 解析为可同步滚动行 → 获取成功即本地保存；支持手动粘贴歌词（优先级高于 AI 结果）。

### 4.6 密钥与敏感信息安全

- **唯一允许的持久化位置**：`flutter_secure_storage`（系统安全区）。加密密钥由平台安全硬件持有（Android Keystore + EncryptedSharedPreferences / Keychain / DPAPI / libsecret），安装包内不含任何密钥材料，反编译不可得。
- **明文禁区**：AppStateStore 的普通 JSON、shared_preferences、普通文件、日志、崩溃上报、Rx 状态持久化——一律禁止写入 API Key，代码评审硬性检查项。
- Web 端无系统安全区：降级为会话级内存保存（本次运行有效，不落盘），UI 明示；不提供明文文件兜底。
- Key 在 UI 脱敏展示（前 4 后 4）；提供"测试连接"；仅发送至所选供应商域名。
- `secure_store_service` 封装全部读写，Key 不进 Controller/Widget 层，用毕可清内存。

### 4.7 B站缓存音频导入

- 目标：读取本地已有的 B站（Android 端）离线缓存，提取**音轨**入库播放。DASH 缓存为 video.m4s / audio.m4s 分离结构，`entry.json` 含标题/UP主/分P等元数据，`audio.m4s` 即 fMP4 容器的音频轨。
- 访问方式：Android 11+ 受分区存储限制，通过系统文件选择器（SAF）由用户授权 B站 `download` 目录；部分 ROM 可能受限，降级方案为引导用户先用系统文件管理器把缓存拷贝到可访问目录；桌面端无此限制。
- 提取策略两级：① 默认直接以 audio.m4s（fMP4）作为播放源，ExoPlayer/mpv 均可解码，零转换成本；② 可选引入 ffmpeg 系包转封装为标准 .m4a（便于便携导出），见选型表注意事项。
- 导入产物与本地歌曲同构（`Song.source = bili`），元数据取自 entry.json，复用曲库展示、搜索、歌单全部能力，不新增一套管理逻辑。

## 5. 编码规范与质量要求

- **Lint**：沿用 `analysis_options.yaml` 中 `flutter_lints` 规则集，CI/本地提交前零 warning。
- **命名**：文件蛇形命名（`player_service.dart`），类大驼峰，成员小驼峰；私有成员 `_` 前缀。
- **模型**：统一不可变模型（`final` 字段 + `copyWith`），JSON 序列化手写或用 Dart 3 便捷写法，不引入代码生成器（保持依赖极简）。
- **错误处理**：Repository 层捕获底层异常 → 抛业务异常（core/exceptions）；UI 层统一通过 SnackBar/Dialog 呈现。
- **注释**：仅对"为什么"与公开 API 写注释，公开类/方法写 Dart Doc。
- **复用**：通用 UI（封面占位、加载态、空态、错误重试组件）沉淀到 `core/` 或共享 widgets，禁止复制粘贴页面代码。
- **测试**：ViewModel 与 Repository 的单元测试必须可 Mock 依赖运行；播放器实现层允许以集成方式验证。
- **安全**：敏感凭据（API Key 等）只经 `secure_store_service` 存取，禁止出现在明文存储、日志与错误上报中；代码评审时作为硬性检查项。

## 6. 平台适配要点

| 平台 | 要点 |
|---|---|
| Android | 后台播放需前台服务（just_audio_background 自动处理）；读本地文件需存储权限声明与运行时申请；B站缓存目录访问依赖 SAF 授权（11+ 分区存储限制） |
| iOS/macOS | 沙盒限制：本地导入依赖 picker 授权；App Transport Security 对 http 源需例外配置 |
| Windows/Linux | 音频后端差异（必要时引入 just_audio_media_kit）；窗口尺寸适配与鼠标交互 |
| Web | 浏览器自动播放策略限制（需用户手势触发）；file_picker 行为差异；无系统安全区，AI Key 仅会话级保存；首次落地可降级为只读演示 |

各端差异只在初始化/适配层处理（条件导入或启动期注入实现），业务层无感知。
