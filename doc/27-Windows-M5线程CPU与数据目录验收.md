## 2. UI 线程 CPU 诊断口径

既有 `FrameTiming.buildDuration` 是 UI 帧的墙钟时长，整机 PDH 百分比不是应用线程耗时，VM CPU profiler 的统计样本也不能直接换算成线程 CPU 毫秒。因此本轮在仅用于 Profile 的万曲滚动探针加入 Windows `GetThreadTimes`：从相同 Dart UI 线程在测量首尾各读取一次用户态和内核态累计 CPU，用单调墙钟记录区间，核对进程与线程身份，并将帧 CSV 视为近同期的 30 秒窗口。采样器不附加 VM profiler，不逐帧调用原生 API。

首个 post-frame 读取发生在测量首帧 UI 构建后，末个发生在末帧 UI 构建后。Flutter 的 `currentSystemFrameTimeStamp` 是引擎传入 `onBeginFrame` 的原始时间戳，而 `FrameTiming.vsyncStart` 记录操作系统 vsync 信号，两者不保证相等；独立校验须保留首末实际偏差与预先限定的容差，不把相近时间说成精确同帧。线程 CPU 覆盖区间内同一线程的帧内及帧外工作；近同期帧 build 墙钟之和只用作量级参照，二者不能逐帧相减并直接定性等待原因。新探针的帧率不能直接与旧版本探针当成严格 A/B，因为探针本身增加了测量字段，现有 `dev.14` 产品包与此前 7,774 个 CPU 样本均不能倒算线程 CPU。

代码审查确认宽曲库行有五段、窄行有三段独立 `Text`，分别承担截断、列宽和语义；贸然合并会改变内容行为。无封面回退的 `Container` 只增加一个可由 `ColoredBox` 代替的包装层，但 CPU 样本无法归因到它，而且每行少一层的预期收益有限。本轮先取得线程时间证据，再决定是否做保留内容、焦点与语义的单变量试验。

首次新探针 `ui-cpu-r1` 自行退出码 1，完整原始 JSON、CSV、session 与 runner 错误仍在 `D:\dev\setup\verification\m5-ui-thread-cpu`。该轮同一 PID 46180 / TID 46608 的原生 CPU 计数可读，但代码错误要求原始 `onBeginFrame` 时间戳必须与 CSV 的 `vsyncStart` 完全相等；首端相差 12.117 ms、末端相差 6.058 ms，因此正确判为无效。这轮帧率及 CPU 值不参与最终有效诊断或性能达标判断。随后按上述两个时钟的实际语义修订为带明示偏差与预设容差的近同期窗口校验，并保留这次失败供审计。
