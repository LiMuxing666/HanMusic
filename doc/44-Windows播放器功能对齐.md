# Windows 播放器功能对齐与验收清单

本文记录本轮 Windows 功能增量、常用操作和验证边界。第一批为收藏、自建歌单、下一首播放，以及曲库排序、批量操作和应用内快捷键；第二批按用户选择同时推进本地歌词、歌曲详情和 Windows 系统交互三个功能组。

**三类功能均已加入当前开发分支。** 自动测试、Windows 原生验收及剩余验证边界见第 5 节；这里的功能对齐不等同于正式发行验收。

## 3. 常用操作

### 收藏与歌单

1. 在歌曲行或播放区域使用收藏按钮，将歌曲加入“我喜欢”；再次操作可取消收藏。
2. 打开“我的歌单”，通过歌单选择菜单切换“我喜欢”或自建歌单。用“新建歌单”创建列表，名称去除两端空白后为 1–100 个字符，不能与现有歌单重名。
3. 从歌曲菜单选择加入歌单。重复加入会显示已有数量，不产生重复歌曲；本地和在线歌曲可以保存在同一歌单。
4. 歌单内可播放单曲或整单、全部加入队列、上下调整顺序或移除歌曲。整单播放采用歌单顺序并保持现有播放模式；随机模式下先播放选中的起始歌曲，再按随机规则切歌。
5. 删除自建歌单需要确认。**删除歌单保留曲库、现有播放队列和源音频；从歌单移除歌曲也不删除音频文件。** 从曲库移除索引后，其他歌单可以保留该歌曲快照。

缺失的本地文件、音乐源已经移除的在线歌曲会在播放/批量入队时跳过；歌单记录仍保留，便于恢复文件或重新配置音乐源。文件状态检查会同步曲库记录，并检查仅保存在歌单中的本地歌曲。

### 下一首、排序及批量操作

歌曲菜单中的“加入播放队列”追加到队列；“下一首播放”优先安排这首歌，不打断正在播放的曲目。当前为空队列时只建立待播项，需要点击播放。睡眠定时仍可优先停止播放。

曲库排序只改变当前视图，不直接重排已经建立的播放队列。相同排序字段保持原先顺序；缺少歌手/专辑的信息排在末尾；导入顺序降序表示最近导入优先。“播放搜索结果”和批量入队使用操作时的最新筛选/排序结果，并报告已加入、已存在与不可用歌曲的数量。

快捷键说明可从界面上的“键盘快捷键”入口查看：

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+Space | 播放、暂停或重试 |
| Ctrl+← / → | 上一首 / 下一首 |
| Ctrl+Shift+← / → | 快退 / 快进 5 秒 |
| Ctrl+↑ / ↓ | 音量增加 / 减少 5% |
| Ctrl+M | 静音 / 恢复音量 |
| Ctrl+F | 聚焦当前页面搜索框 |

这些是应用内快捷键。第二批 Windows 系统媒体键通过系统媒体会话接入，需要单独进行原生验证。

### 本地歌词

将 `歌曲名.lrc` 放在对应音频的同一目录，例如 `D:\Music\夜航.flac` 对应 `D:\Music\夜航.lrc`。歌词文件使用 UTF-8 或 GBK，限制为 1 MB，读取超时会显示提示；没有有效时间标签时按纯文本显示。

在“正在播放”页面查看歌词。带时间标签的歌词按播放进度高亮并自动跟随；手动滚动后暂时停止跟随，可点击“回到当前行”恢复。修改磁盘上的歌词后，用“重新读取歌词”加载。没有同名文件、文件无法读取或在线歌曲未关联本地歌词时，界面说明原因，不应保留上一首歌词。

本轮读取旁置 LRC 文件，不修改源音频或歌词文件；内嵌歌词、在线歌词搜索、手工歌词编辑和 AI 歌词尚未纳入此功能。

### 歌曲详情与文件操作

从歌曲菜单或当前曲目的详情入口打开“歌曲详情”。本地歌曲显示标题、歌手、专辑、时长、格式、文件路径，以及读取到的文件大小或缺失状态。点击“复制文件路径”复制原路径；Windows 下“打开文件位置”请求 Explorer 选中文件。

在线歌曲显示音乐源名称、源标识和歌曲标识，“复制歌曲标识”复制稳定的内部身份，不复制临时解析出来的 HTTP 播放地址。在线歌曲没有本地 Explorer 定位入口。详情页用于查看信息，本轮没有写回音频标签的功能。

### Windows 媒体与托盘

启用原生媒体会话后，可从 Windows 媒体界面或键盘媒体键操作播放、暂停、上一首和下一首。托盘入口用于显示/隐藏主窗口，托盘右键菜单提供显示窗口、播放/暂停、切歌和退出。

侧栏底部的“收起到托盘（继续播放）”仅在原生托盘可用时出现；没有可恢复窗口的托盘图标时不隐藏主窗口。关闭窗口仍正常退出并保存，收起只是隐藏窗口并继续播放。托盘退出也经过既有保存/失败处理流程。

## 4. 数据保存与迁移

应用状态新增 `playlists`，写入版本升级为 **schema 3**。schema 1/2 仍可读取，迁移时歌单列表为空，服务会补足内置“我喜欢”；下一次成功保存写入 schema 3。schema 3 必须包含格式有效的歌单列表，重复 ID、损坏字段或非法歌曲身份会被拒绝，并按既有机制尝试有效备份。更高版本数据仍进入只读保护，不强行降级覆盖。

歌单保存 ID、名称、歌曲元数据快照及 UTC 创建/更新时间。完整歌曲快照使不在曲库中的本地项和在线项能够恢复；在线项仍只保存稳定的源/歌曲身份，加载时重新解析播放地址，禁止将实际 HTTP 播放地址作为歌曲身份落盘。后台曲库元数据和缺失状态同步不改变歌单的用户编辑时间。

旧测试/诊断调用即使没有传入歌单服务，也保留已经保存的 schema 3 歌单，避免播放状态保存覆盖歌单。文件仍沿用已有有效备份与数据目录锁机制；删除歌单或移除索引始终不等同于删除源音频。

### 实机发现并修复的问题

1. 同目录 LRC 被底层 mpv 自动当作字幕加载，音频专用构建产生字幕错误，旧桥接将它升级为播放失败。Windows 现在直接使用已有 media_kit 解码器，加载前关闭 `sub-auto`；每次加载独立会话并保留真实解码错误。配置或打开操作挂起时也能立即响应错误，避免等待超时。
2. Explorer `/select` 参数方式只打开目录但未选中文件。改用后台 COM 线程的 `SHParseDisplayName` 和 `SHOpenFolderAndSelectItems`，主窗口不等待文件解析，路径不经过命令行解释；最终实机已确认文件被选中。
3. 托盘菜单使用嵌套消息循环；增加独立共享状态保护，窗口关闭后不再访问已释放对象。
4. 键盘打开托盘菜单时原先直接使用鼠标位置。现在 v4 上下文菜单通过 `Shell_NotifyIconGetRect` 取得图标位置，鼠标已在图标内时保留原位置；同时记录 `NIM_SETVERSION` 的结果，失败时按旧版回调解释事件并保留鼠标定位。最终 Release 已验证鼠标远离图标时，用菜单键打开仍定位在图标旁。
5. 隐藏主窗口后，原托盘菜单底部被 Windows 11 的隐藏图标浮层遮挡：“退出”的实际命中对象是 Explorer 内的其他图标。菜单现在仅在存续期临时提升 owner 层级，结束或关闭桥接时恢复原状态，并处理菜单重入及 `SetWindowPos` 同步重入关闭的情况。未放宽测试的菜单文字、PID、UIA 和 Win32 命中校验；修复后同一位置可正常点击退出，菜单关闭也不会使主窗口遗留置顶。
