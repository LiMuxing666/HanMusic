# Windows M5 播放控制与退出保存

日期：2026-09-30。基线提交 `5edfac6`，本轮推进开发预览 `0.1.0-dev.10+10`。证据目录为 `D:\dev\setup\verification\m5-player-controls`；SDK、Pub、Gradle、临时文件、应用数据和预览产物继续放在 D 盘，没有新增或升级依赖。

## 1. 连续音量与跳转操作

此前音量请求失败会直接回滚到请求开始前的界面值。较早请求延迟失败时，即使较新的请求已成功或正在执行，仍可能覆盖新设置。连续多个请求均失败时，简单回滚到前一个请求值也可能回到未成功应用的值。

普通跳转只检查歌曲加载代际，同曲连续跳转的旧 Future 成功仍可能覆盖新目标；切歌后的旧跳转失败也会向新歌曲显示错误。本轮为完成回调补充请求归属，并保留当前有效失败的提示、恢复音量基线和重新播放的行为。

音量以最近成功的手动请求或恢复值作为回退基线；使用固定数量字段处理最新失败、迟到成功与恢复，不保留无限增长的请求历史。普通跳转与重播定位共用请求序号，新定位可以替代旧重播定位，但不会丢弃原有的播放意图或吞掉之后真正的播放错误。

本机锁定的 just_audio 0.10.6 在等待平台跳转前发布目标位置，media_kit 1.2.6 已串行处理原生命令。本轮不额外添加应用层原生命令队列，不据受控 Future 完成顺序推断正常 Windows 原生命令必然倒序执行。没有操作 ID 的后端事件流仍保留原有边界，不能把回调保护说成完整过滤迟到原生事件。

## 2. 进度条失效手势

拖动期间同曲发生错误或进入重载，进度条会被禁用；原实现只在有效的松手回调清除预览，可能留下旧位置。同曲恢复后继续复用组件状态，还可能把恢复前的手势提交给新一轮播放。

本轮同时清理失效预览与手势，覆盖禁用期间松手、恢复后才松手以及随后正常新拖动。同曲重载可能在一帧内完成，单看 enabled 的最终值不足以判断；因此组件还读取只读的播放选择代次，在身份变化时失效旧交互，不改变原有播放计数或流程。使用 Widget 的真实手势序列验证，并保留 Tab/方向键与辅助功能增加进度的动作，不代替实际 Windows 鼠标或系统 DPI 验收。

## 3. 网络源保存与退出

原退出流程只检查播放器状态保存，网络源配置在后续清理阶段才等待关闭。若用户提交配置后立即退出，配置落盘失败或等待超时可能被忽略，应用直接退出。

退出开始时、等待暂停之前捕获仍在进行的源配置变更，并将结果纳入可取消的保存检查；不能先不可逆地关闭服务再决定是否取消。退出前已经完成并反馈的历史失败不永久阻塞以后退出。配置保存后的自动切源也在检查范围内，不能漏掉采样间隙内已经完成的失败；累计失败序号用于保留这类结果，不增加超时后残留的事件订阅。

整个退出请求期间，编辑器不自动关闭；确认覆盖其上时也不能误弹出上层路由。取消退出后保留已保存的编辑器，用户仍可手动关闭或继续编辑。这样还避免 Flutter Debug 在等待退出响应时，继续访问已经由编辑器关闭而销毁的生命周期观察者；未把该 Debug 断言说成 Release 崩溃。退出提示同时覆盖保存失败与仍在等待的情况。
