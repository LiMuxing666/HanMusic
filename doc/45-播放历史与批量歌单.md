# 播放历史与批量歌单

本轮在 `codex/windows-library-controls` 工作副本继续增加最近播放、曲库多选和 HanMusic JSON 歌单交换功能，尚未发布新版本。上一轮媒体键与托盘的已完成原生验收保留在[功能对齐清单](44-Windows播放器功能对齐.md)，本轮验证进度单独记录在本文末尾。

## 最近播放

侧栏打开“最近播放”，可按歌曲标题、歌手和专辑搜索，并查看最近播放时间与累计次数。点击可用歌曲开始播放，歌曲菜单提供收藏、下一首播放、加入队列/歌单、歌曲详情及移除历史等操作。缺失的本地文件或没有可用音乐源的在线项会保留记录，但不能直接播放。

记录规则如下：

- 每次选曲累计观察到 **10 秒有效播放**后记一次。用单调时钟与向前推进的音频位置共同计算，暂停、缓冲、加载、恢复旧进度及手动跳转不增加累计时长。
- 同一次选曲暂停后继续播放可接着累计；达到阈值后不会因继续播放或在曲尾重新开始而重复计数。重新选中同一首并再次达到阈值，更新最近时间并增加次数。
- 每首歌曲仅保留一条记录，按最近播放时间排序，最多保留 **200 首**；超出后移除最早记录。
- 支持单条移除和确认后清空。当前曲目对应的历史被移除后，本次选曲剩余播放不立即重新生成记录；重新选曲后恢复正常计数。

清理历史只改变历史列表，保留当前播放、队列、曲库、歌单和源音频。历史中的歌曲元数据和缺失状态可随曲库刷新，刷新不增加播放次数，也不改写播放时间。

## 曲库多选与批量操作

曲库操作中进入选择模式后，点击歌曲切换勾选状态。未进入选择模式且没有按修饰键时，普通点击仍按既有行为播放歌曲。

| 操作 | 行为 |
| --- | --- |
| Ctrl+点击 | 进入选择模式，切换单首歌曲的选择状态 |
| Shift+点击 | 按当前搜索、排序后的列表选择从锚点到目标的连续范围 |
| Ctrl+Shift+点击 | 在已有选择上追加连续范围 |
| Ctrl+A / 全选可见歌曲 | 选择当前搜索结果中的所有歌曲，包括需要滚动才能看到的结果 |
| Esc / 完成选择 | 退出选择模式并清空勾选 |

快捷键只在曲库页面生效；输入框与弹窗保留自己的键盘行为。搜索框内 Ctrl+A 仍全选文本，Esc 仍清空搜索。更改搜索条件后，选择会与当前结果同步，避免批量操作误处理已经不在结果中的歌曲。

选择工具栏提供：

- **批量入队**：按当前列表顺序追加可用歌曲，去重并反馈新增、已存在和不可用数量，不自动开始播放。
- **加入歌单**：按当前可见顺序将所选歌曲加入指定歌单，保留歌单的去重规则；确认时使用已捕获的歌曲顺序。
- **移除曲库索引**：确认后移除曲库索引和对应队列项，保留歌单、播放历史及磁盘上的音频文件。

## HanMusic JSON 歌单导入与导出

在“我的歌单”使用“导入歌单”或“导出当前歌单”。当前格式为 HanMusic JSON，格式标识 `hanmusic-playlist`、版本 `1`，推荐扩展名 `.hanmusic.json`。它与应用状态文件的 schema 版本独立。

导入选择 JSON 文件后，先完整校验内容，再新建歌单；重名时添加编号，例如“夜航 (2)”。导入不会覆盖现有歌单、修改原文件或替换播放队列；取消选择保留原状态。格式错误、重复歌曲、非法歌曲身份、超限文件等会显示错误，且不会留下部分导入的歌单。

导出先选择**目标文件夹**，应用按歌单名生成文件名，例如 `HanMusic-夜航.hanmusic.json`。同名文件已经存在时生成 `HanMusic-夜航 (2).hanmusic.json` 等编号文件，不覆盖已有文件；成功后显示实际保存位置。

单文件上限为 **4 MB（4 × 1024 × 1024 字节）**，单歌单最多 **5000 首**；导入和导出均受限制。文件保存歌单名、歌曲元数据以及本地文件路径或在线歌曲的稳定源/歌曲标识，不包含音频、封面缓存、临时 HTTP 播放地址或音乐源配置。

导入时重新检查本地文件，最多 8 路并发、整体等待 3 秒；缺失、不可访问或超时的项保留并标记为不可用，之后可从曲库“刷新文件状态”重新检查。跨机传递歌单后，本地歌曲路径仍需在目标机器可用；文件本身不会复制音频或自动寻找新路径。在线歌曲需要配置相同稳定源标识的可用音乐源，播放时重新解析地址。尚不支持 M3U、PLS、商业平台账号同步或将音频打包下载。

## 状态保存与迁移

应用状态升级为 **schema 4**，新增 `history`，每条包含歌曲身份/元数据、UTC 最近播放时间和正整数播放次数。保存时捕获历史列表快照，与曲库、队列、歌单及播放状态一起写入，沿用串行写入、有效备份和数据目录锁。

schema 1/2/3 仍可读取，旧数据的历史初始化为空；schema 3 的歌单继续保留，缺少内置“我喜欢”时由歌单服务补足。下一次成功保存写入 schema 4。历史缺失、无效、重复歌曲身份或超过 200 条时视为无效快照，按现有规则尝试有效备份。

遇到比 schema 4 更高的版本时进入只读保护，保留原文件，不用旧备份降级覆盖。主文件与备份都损坏时也保留原文件并停止保存。退出仍等待保存；用户取消退出后，历史和其他服务继续可用。
